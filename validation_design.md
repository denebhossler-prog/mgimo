# План проверки
Ожидаемое изменение (с порогом, заданным ДО запуска; пп vs относительное %) · единица счёта и единица распределения (кластер: семья → вся семья в одну ветку) ·
группа сравнения (случайная; иначе объяснить сопоставимость) · анализ «всех включённых» (intention-to-treat), не только откликнувшихся ·
подходящий случай одинаково фиксируется в обеих ветках (теневая запись) · срок набора + наблюдения · мощность (`tools/power.py`) и темп набора ·
нежелательные последствия + стоп-правила · решающие правила: расширять / менять / продлить / остановить · пересмотр: одно подглядывание — по заранее строгой границе.
Если срока хватает только на понятность и исполнение — так и написать, эффект на связь проверять отдельно.
